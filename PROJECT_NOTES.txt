CHAPTER 1: INTRODUCTION & FULL STACK OVERVIEW
===============================================================================

0001: Photopedia is a high-performance visual storytelling application built using a decoupled
0002: full-stack architecture: Next.js 16 App Router on the client and NestJS on the server.
0003: 
0004: In classic LAMP stack (Linux, Apache, MySQL, PHP / WordPress), single-threaded PHP scripts
0005: handle routing, database queries, and HTML template generation synchronously during a single
0006: request cycle. In Photopedia, responsibility is strictly divided into specialized tiers:
0007: 
0008: 1. FRONTEND TIER (Next.js 16 + React 19 + TypeScript + Tailwind CSS):
0009:    - Runs in the user's browser as a Single Page Application (SPA).
0010:    - Handles dynamic UI updates, client state, file drag-and-drop, and lightboxes.
0011:    - Communicates asynchronously with the backend via HTTP JSON REST API requests.
0012: 
0013: 2. BACKEND TIER (NestJS + Express + TypeScript + Passport JWT):
0014:    - Runs continuously as a Node.js web server process on port 4000.
0015:    - Provides structured controllers, validation pipes, auth guards, and business services.
0016:    - Processes HTTP requests, executes business logic, and manages static media uploads.
0017: 
0018: 3. DATABASE TIER (SQLite / PostgreSQL + Prisma ORM):
0019:    - Relational data store managed via type-safe Prisma ORM queries.
0020:    - Handles transactional schema modeling, relational foreign key cascading, and seeding.
0021: 
0022: 4. STORAGE TIER (StorageModule + IStorageProvider Contract):
0023:    - Multi-provider media upload engine supporting Local Storage (`server/uploads/`),
0024:      Cloudflare R2, AWS S3, and DigitalOcean Spaces.
0025: 
0026: SYSTEM COMMUNICATIONS MAP:
0027: Browser (React 19 / Next.js 16)
0028:    │
0029:    ▼  [HTTP REST Requests with Authorization: Bearer <JWT>]
0030: NestJS Controllers (server/src/*/*.controller.ts)
0031:    │
0032:    ▼  [ValidationPipe / JwtAuthGuard / RolesGuard]
0033: NestJS Services (server/src/*/*.service.ts)
0034:    │
0035:    ├─────────────────────────────┐
0036:    ▼                             ▼
0037: StorageModule (IStorageProvider)   Prisma ORM Client (PrismaService)
0038:    │                             │
0039:    ▼                             ▼
0040: Local Disk / R2 / S3 / Spaces     SQLite / PostgreSQL Database

CHAPTER 2: TYPESCRIPT & NODE.JS CORE CONCEPTS
===============================================================================

0041: 2.1 WHAT IS TYPESCRIPT?
0042: TypeScript is a typed superset of JavaScript compiled down to plain JavaScript.
0043: In standard PHP, variables can dynamically change type unless explicitly type-hinted.
0044: TypeScript provides compile-time safety, detecting type errors before code reaches runtime.
0045: 
0046: 2.2 KEY TYPESCRIPT LANGUAGE FEATURES IN PHOTOPEDIA:
0047: 
0048: A) INTERFACES & TYPE ALIASES:
0049: An interface defines the exact shape of an object.
0050: Example from `server/src/media/storage/storage.interface.ts`:
0051: 
0052:     export interface StorageFile {
0053:       buffer: Buffer;
0054:       originalname: string;
0055:       mimetype: string;
0056:       size: number;
0057:     }
0058: 
0059: If any function receives a `StorageFile` missing `buffer` or `mimetype`, TypeScript flags an error.
0060: 
0061: B) GENERICS `<T>`:
0062: Generics allow writing reusable code that operates on multiple types while maintaining type safety.
0063: Example from `app/lib/api.ts`:
0064: 
0065:     export async function fetchApi<T>(endpoint: string, options: RequestInit = {}): Promise<T> {
0066:       const response = await fetch(`${API_BASE_URL}${endpoint}`, options);
0067:       return response.json();
0068:     }
0069: 
0070: When calling `fetchApi<User[]>('/users')`, TypeScript automatically knows the output is an array of `User` objects.
0071: 
0072: C) ASYNC / AWAIT & PROMISES:
0073: PHP blocks execution on every I/O call (e.g. database query, file write).
0074: Node.js uses non-blocking asynchronous event-driven I/O.
0075: A `Promise` represents a value that will resolve in the future.
0076: `await` pauses execution of an `async` function until the promise settles.
0077: 
0078: Example:
0079:     const user = await this.prisma.user.findUnique({ where: { email } });
0080: 
0081: 2.3 NODE.JS MODULE SYSTEM (ES MODULES vs COMMONJS):
0082: Modern TypeScript uses ES Module syntax (`import { Module } from '@nestjs/common'`).
0083: Node compiles these imports into efficient JavaScript execution graphs.

CHAPTER 3: NEXT.JS 16 APP ROUTER & REACT 19 FRONTEND ARCHITECTURE
===============================================================================

0084: 3.1 WHAT IS NEXT.JS 16?
0085: Next.js is a React framework for building fast web applications with automatic routing,
0086: rendering optimizations, and server side rendering capabilities.
0087: 
0088: 3.2 APP ROUTER FILE-SYSTEM CONVENTIONS:
0089: Next.js maps file directories directly to URL routes:
0090: 
0091: - `app/feed/page.tsx`                   ──► Route: /feed
0092: - `app/feed/[id]/page.tsx font`              ──► Route: /feed/:id (Dynamic post view)
0093: - `app/feed/[id]/edit/page.tsx`         ──► Route: /feed/:id/edit (Author post edit)
0094: - `app/creators/[username]/page.tsx`     ──► Route: /creators/:username (Creator profile)
0095: - `app/category/[slug]/page.tsx`        ──► Route: /category/:slug (Category archive)
0096: - `app/(auth)/login/page.tsx`            ──► Route: /login (Route group ignores parentheses)
0097: 
0098: 3.3 SERVER COMPONENTS vs CLIENT COMPONENTS (`"use client"`):
0099: 
0100: A) SERVER COMPONENTS (Default in Next.js 16):
0101: - Rendered on the server.
0102: - Zero JavaScript sent to client bundle for pure markup.
0103: - Cannot use React state (`useState`) or browser lifecycle hooks (`useEffect`).
0104: 
0105: B) CLIENT COMPONENTS (`"use client"` directive at top of file):
0106: - Shipped to the browser to handle DOM events, user input, and interactive state.
0107: - Used across all Photopedia interactive pages (`FeedPage`, `PostCard`, `LightboxModal`).
0108: 
0109: 3.4 REACT 19 HOOKS USED IN PHOTOPEDIA:
0110: 
0111: 1. `useState`: Holds component state.
0112:    Example: `const [likes, setLikes] = useState(initialLikes);`
0113: 
0114: 2. `useEffect`: Runs side effects (e.g. data fetching, event listeners) after rendering.
0115:    Example: Adding Escape key listener inside `PhotoLightboxModal`.
0116: 
0117: 3. `useCallback`: Memoizes function instances to prevent unnecessary re-renders.
0118:    Example: `fetchFeed` inside `useFeed.ts`.
0119: 
0120: 4. `useParams` & `useRouter`:
0121:    Used for reading dynamic route parameters (`params.id`) and programmatic navigation (`router.push('/feed')`).

CHAPTER 4: NESTJS BACKEND FRAMEWORK & DEPENDENCY INJECTION
===============================================================================

0122: 4.1 NESTJS ARCHITECTURE OVERVIEW:
0123: NestJS is structured into 4 primary building blocks:
0124: 
0125: 1. MODULES (`@Module()`):
0126:    Encapsulates feature domains (`PostsModule`, `AuthModule`, `MediaModule`).
0127: 
0128: 2. CONTROLLERS (`@Controller()`):
0129:    Handles incoming HTTP requests, route parameters, headers, and bodies.
0130: 
0131: 3. SERVICES (`@Injectable()`):
0132:    Contains core business logic, calculations, and data persistence logic.
0133: 
0134: 4. GUARDS (`@UseGuards()`):
0135:    Intercepts requests to enforce security, authentication, and role authorization.
0136: 
0137: 4.2 DEPENDENCY INJECTION (DI) IN ACTION:
0138: Instead of manually instantiating classes (`new PostsService()`), NestJS automatically
0139: injects singletons via class constructors:
0140: 
0141:     @Controller('posts')
0142:     export class PostsController {
0143:       constructor(private readonly postsService: PostsService) {}
0144:     }
0145: 
0146: When an HTTP request hits `PostsController`, NestJS injects the single instance of `PostsService`.

CHAPTER 5: PRISMA ORM & RELATIONAL DATABASE ARCHITECTURE
===============================================================================

0147: 5.1 WHAT IS PRISMA ORM?
0148: Prisma is an open-source, next-generation Object-Relational Mapper (ORM).
0149: In PHP, developers often write raw SQL strings (`$wpdb->prepare("SELECT * FROM wp_posts WHERE...")`).
0150: Prisma provides auto-generated, type-safe query builders based on `schema.prisma`.
0151: 
0152: 5.2 DATABASE MODELS IN PHOTOPEDIA (`server/prisma/schema.prisma`):
0153: 
0154: A) USER MODEL:
0155: Represents platform accounts (Creators & Platform Administrators).
0156: Includes fields for bio, location, camera gear body, lenses, status (`ACTIVE` | `BLOCKED`), and role (`USER` | `ADMIN`).
0157: 
0158: B) POST MODEL:
0159: Represents published photographs. Bound to `User` via `authorId` foreign key.
0160: 
0161: C) EXIFDATA MODEL:
0162: Holds camera metadata (`camera`, `lens`, `aperture`, `shutter`, `iso`).
0163: Has a 1-to-1 relation with `Post` via `@unique` `postId`.
0164: 
0165: D) FOLLOW MODEL:
0166: Manages user social connections via self-referential relations (`followerId` & `followingId`).
0167: Enforces a compound unique constraint (`@@unique([followerId, followingId])`).
0168: 
0169: E) LIKE & COMMENT MODELS:
0170: Track community likes and comments. `Like` uses compound unique index (`@@unique([userId, postId])`).
0171: 
0172: 5.3 PRISMA QUERY EXAMPLES FROM PHOTOPEDIA:
0173: 
0174: 1. Creating a Post with EXIF Data (`server/src/posts/posts.service.ts`):
0175: 
0176:     await this.prisma.post.create({
0177:       data: {
0178:         title,
0179:         image,
0180:         caption,
0181:         category,
0182:         authorId,
0183:         exif: {
0184:           create: { camera, lens, aperture, shutter, iso }
0185:         }
0186:       }
0187:     });
0188: 
0189: 2. Querying Feed with Substring Search & Relational Include:
0190: 
0191:     await this.prisma.post.findMany({
0192:       where: {
0193:         deletedAt: null,
0194:         OR: [
0195:           { title: { contains: search } },
0196:           { category: { contains: search } },
0197:           { author: { name: { contains: search } } }
0198:         ]
0199:       },
0200:       include: {
0201:         author: { select: { name: true, username: true, avatar: true } },
0202:         exif: true,
0203:         _count: { select: { likes: true, comments: true } }
0204:       }
0205:     });

CHAPTER 6: AUTHENTICATION, JWT & AUTHORIZATION GUARDS
===============================================================================

0206: 6.1 AUTHENTICATION ARCHITECTURE:
0207: Photopedia uses JSON Web Token (JWT) stateless authentication.
0208: 
0209: A) PASSWORD HASHING (Bcrypt):
0210: Passwords are hashed using `bcrypt.hash(password, 10)` during registration/seeding.
0211: Raw passwords are NEVER stored in plain text.
0212: 
0213: B) JWT GENERATION:
0214: Upon successful login, `AuthService` signs a JWT containing payload `{ sub: userId, email, role }`.
0215: 
0216: C) JWT VERIFICATION & BLOCKED USER GUARD (`server/src/auth/jwt.strategy.ts`):
0217: Every request with `Authorization: Bearer <token>` passes through `JwtStrategy`:
0218: 
0219:     async validate(payload: any) {
0220:       const user = await this.prisma.user.findUnique({ where: { id: payload.sub } });
0221:       if (!user || user.status === 'BLOCKED') {
0222:         throw new UnauthorizedException('Your account has been blocked by an administrator.');
0223:       }
0224:       return user;
0225:     }
0226: 
0227: D) ROLE AUTHORIZATION GUARD (`server/src/admin/roles.guard.ts`):
0228: Ensures only accounts with `role === 'ADMIN'` can access `/admin/*` management routes.

0247: 2. `R2StorageProvider` (`server/src/media/storage/r2.storage.ts`):

0249: 
0250: 3. `S3StorageProvider` (`server/src/media/storage/s3.storage.ts`):

0252: 
0253: 4. `SpacesStorageProvider` (`server/src/media/storage/spaces.storage.ts`):

CHAPTER 12: LAMP / WORDPRESS TO MODERN STACK GLOSSARY & COMPARISON GUIDE
===============================================================================

0348: API (Application Programming Interface):
0349: - Simple: Structured HTTP endpoints returning JSON data instead of rendered HTML.
0350: - In Photopedia: NestJS controllers returning JSON payloads to Next.js client.
0351: 
0352: BCRYPT:
0353: - Simple: Adaptive password hashing function.
0354: - In Photopedia: Used in `AuthService` to securely hash passwords before database write.
0355: 
0356: DTO (Data Transfer Object):
0357: - Simple: Class defining and validating incoming request payloads.
0358: - In Photopedia: `CreatePostDto`, `UploadMediaDto`, `UpdateProfileDto`.
0359: 
0360: GUARD:
0361: - Simple: Authorization middleware executing before route handlers.
0362: - In Photopedia: `JwtAuthGuard` (validates JWT) and `RolesGuard` (enforces `ADMIN` role).
0363: 
0364: ISTORAGEPROVIDER:
0365: - Simple: Interface contract unifying file operations across Local Storage and Cloud providers.
0366: - In Photopedia: Implemented by `LocalStorageProvider`, `R2StorageProvider`, `S3StorageProvider`, `SpacesStorageProvider`.
0367: 
0368: JWT (JSON Web Token):
0369: - Simple: Encrypted stateless identity token stored by client in `localStorage`.
0370: - In Photopedia: Passed in `Authorization: Bearer <token>` header on authenticated calls.
0371: 
0372: MONOREPO:
0373: - Simple: Single Git repository containing both client frontend and server backend projects.
0374: 
0375: PRISMA ORM:
0376: - Simple: Type-safe database client mapping TypeScript code directly to SQLite/PostgreSQL SQL.
0377: 
0378: REACT 19 & NEXT.JS 16:
0379: - Simple: Component-based UI framework handling routing, DOM rendering, and client state.
0380: 
0381: SHIMMER SKELETON:
0382: - Simple: Animated CSS pulse effect providing visual loading feedback before data arrives.
0383: 
0384: SOFT DELETION (`deletedAt`):
0385: - Simple: Setting `deletedAt` timestamp instead of physically removing database rows.
0386: - In Photopedia: Excludes deleted posts (`deletedAt: null`) while preserving audit records.

CHAPTER 13: MODULAR DTO ARCHITECTURE, RESPONSE ENVELOPES & ERROR FILTERS
===============================================================================

0387: 13.1 MODULAR DTO (DATA TRANSFER OBJECT) ARCHITECTURE:
0388: In high-grade enterprise applications, controller request bodies are strictly validated using
0389: `class-validator` and `class-transformer` DTO classes located in domain `dto/` packages:
0390: - `Auth`: `RegisterDto`, `LoginDto`
0391: - `Posts`: `CreatePostDto`, `UpdatePostDto`, `AddCommentDto`, `FlagPostDto`
0392: - `Users`: `UpdateProfileDto`
0393: - `Media`: `UploadMediaDto`

0394: 13.2 STANDARDIZED PRETTY RESPONSE ENVELOPE (`TransformInterceptor`):
0395: All successful NestJS controller return payloads are intercepted by `TransformInterceptor`
0396: (`server/src/common/interceptors/transform.interceptor.ts`) and wrapped in a clean, pretty structure:
0397: {
0398:   "statusCode": 200,
0399:   "success": true,
0400:   "message": "Request successful",
0401:   "data": { ... },
0402:   "path": "/users/1",
0403:   "timestamp": "2026-08-13T15:05:03.863Z"
0404: }

0405: 13.3 GLOBAL HTTP EXCEPTION FILTER (`HttpExceptionFilter`):
0406: Unhandled exceptions are intercepted by `HttpExceptionFilter`
0407: (`server/src/common/filters/http-exception.filter.ts`) and formatted into structured error JSON:
0408: {
0409:   "statusCode": 401,
0410:   "success": false,
0411:   "error": "UnauthorizedException",
0412:   "message": "Invalid email or password",
0413:   "path": "/auth/login",
0414:   "timestamp": "2026-08-13T15:02:35.000Z"
0415: }

0416: 13.4 LOWERCASE ROLE & STATUS STANDARDIZATION:
0417: Database user roles (`"user"`, `"admin"`) and user statuses (`"active"`, `"pending"`, `"blocked"`)
0418: are standardized to lowercase across Prisma schema defaults, seed scripts, NestJS auth guards, and React admin panels.
